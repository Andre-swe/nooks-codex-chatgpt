# Record each useful design cycle

Keep this in revision reasons and the working conversation or a local note.
Do not claim the server persists fields it does not expose. Record observations
and explicitly marked inferences.

```text
Build / system:
Original request and source-photo identifier:
Photo recorded: yes / no / unavailable
Scale, piece/time budget, palette, inventory:
Current saved revision / best valid revision:

Requirement questions:
Q1: object exists?                      depends on []
Q2: distinctive feature exists?         depends on [Q1]
Q3: feature has requested pose/colour?  depends on [Q2]
Each answer: yes / no / unverified, evidence from a named saved view.

Construction: pass / fail / incomplete; checker, revision and findings.
Source comparison (matched / different / unverified + evidence):
- silhouette
- relative proportions
- pose
- negative space
- part density and visible part scale
- distinctive features
- colour placement

Design quality: form, surfaces, part usage, economy; evidence and weaknesses.
Compared cameras: source-matched, front, side, back, top, three-quarter.
Largest mismatch:
Hypothesis / proposed change:
Previous-versus-current comparison:
Keep current or previous, and why:
Next action / stop reason:
```

Keep original requirements visible during repairs. A child question cannot
count when its parent object is absent. Unverified items do not become passes
because the model's program says they should exist.

A reference chair's questions might concern a reclining back, thin arm rails,
face-on end discs, shallow seat, compact feet and open lattice. These are
examples for that source, not required details for every chair.

Retain the better valid candidate when a change worsens source alignment.
Report necessary deviations and unknowns. An unavailable reviewer is a
capability limit, not evidence of a good design.
